Backend reference

This page shows what each backend file does and which functions each API route calls.

Source revision a731fb1

Files

Top level

Starts the app and sets up logging.

server.py
Creates the FastAPI app and prepares the database on startup.
logging_config.py
Sets up the application and sync log files.

routes/

The web API the frontend calls. Each handler checks its input, then either reads through database/reader.py and turns the rows into JSON, or calls a database/ report. The sync endpoints hand off to sync/. Details: docs/references/api.md.

videos.py
Serves the Videos page and single-video data.
playlists.py
Serves the Playlists page and single-playlist data.
analytics.py
Serves the Analytics pages: charts, top videos, traffic sources, search terms, and related videos.
comments.py
Serves the comment feeds for the channel, a video, or a playlist.
synchronization.py
Starts and stops syncs, reports progress, and returns sync history.
metadata.py
Returns the earliest publish year for the year dropdowns.
video_scope.py
Returns 404 when a video isn't one of this channel's or a playlist doesn't exist, and looks up the videos in a playlist for the playlist statistics and analytics endpoints. Defines no endpoints.

database/

Everything that touches SQLite. All reads go through reader.py and all inserts and updates through writer.py; the domain files hold the deletes, the sync-run log, and the reports that do calculations of their own. Details: docs/references/database.md.

dataclasses/
One small data class per table, such as Video or Comment. They only hold values and convert to and from dictionaries; they never run queries.
tables.py
Knows which class belongs to which table and which columns identify a row. Shared by the reader and the writer.
reader.py
Runs every read, fetches only the columns asked for, and returns filled-in data classes.
writer.py
Saves data classes: updates the row with the same key or inserts a new one, and leaves any field that is None as it was.
queries.py
Holds the SQL for joined, grouped, and ranked reads that more than one caller needs. It builds queries but never runs them.
video_statistics.py
Calculates the Legacy/New statistics shown in the stats bar.
videos.py
Deletes videos no longer on the channel.
playlists.py
Deletes removed playlists, and a playlist's items before they are re-saved.
analytics.py
Builds the zero-filled daily chart data.
traffic_sources.py
Builds the zero-filled traffic-source chart data and per-source top videos.
related_videos.py
Builds the Related Video referrer list with its total.
comments.py
Removes comment authors no comment uses.
sync_runs.py
Saves the history of sync runs and groups it into pages of syncs.
connection.py
Opens database connections and creates the tables.

sync/

Downloads data from YouTube and stores it. Details: docs/references/sync.md.

orchestration.py
Runs a sync plan stage by stage and records each stage's result.
stages.py
Contains the code for each of the nine stages.
plans.py
Checks that a requested plan is valid and sets the order stages run in.
status.py
Tracks live progress and handles stop requests.
coverage.py
Works out which months still need downloading.
write_preparation.py
Checks a month of search terms or Related Video referrers, adds up repeats, and turns them into data classes to save.
monthly_insights.py
Splits date ranges into calendar months.
scheduler.py
Is an unused daily-sync helper; nothing calls it.

youtube/

Talks to Google. Only sync/ uses it. Details: docs/references/sync.md.

data_api.py
Fetches channel info, videos, playlists, and comments from the YouTube Data API.
analytics_api.py
Fetches daily metrics, traffic sources, search terms, and related videos from the YouTube Analytics API.
auth.py
Handles the Google sign-in and keeps the token fresh.

Schema and scripts

schema.sql
Defines the database tables.
scripts/issue-48-migration.py
Adds the videos.own column to an older database.
scripts/issue-62-migration.py
Fills in sync coverage for an older database.

Route functions

What each read the routes use gives back, and which endpoints use it. Names starting with queries. are SQL definitions in database/queries.py; the route runs them through database/reader.py and converts the result to JSON. The others are functions that do their own calculation. These only count this channel's own videos. Videos from other channels that are stored only because they sent viewers here through Related Videos never appear.

Videos

Handled in routes/videos.py and routes/metadata.py.

Read
Returns
Used by
queries.video_catalog
Returns one page of videos plus the total count for paging. Each video includes its lifetime earnings in SGD and lifetime watch hours. The list can be sorted and filtered by title, publish date, type and privacy. Given a list of video IDs it covers only those videos, each once: one ID for a single video, or a playlist's videos for its Videos tab.
GET /videos
GET /videos/{id} (that one video)
GET /playlists/{id}/videos (the playlist's video IDs)
get_video_stats
Returns the numbers in the stats bar on the Videos and Analytics pages. Videos and Shorts are each split into legacy (published before the start date) and new (published within the date range), and each group gets a count plus its views and earnings within the date range. It also returns lifetime comment totals and how many videos are public, private and unlisted. With no date range it uses the full span of stored analytics. Given a list of video IDs, it returns the same numbers for just those videos (each counted once), and its default date range comes from their analytics only. Lives in database/video_statistics.py.
GET /videos/stats
GET /playlists/{id}/videos/stats (the playlist's video IDs)
queries.videos_published
Returns the videos published within the date range (ID, title, date, thumbnail and type), oldest first. The charts use it to mark the days videos were uploaded. Given a playlist ID, the route passes that playlist's video IDs so only those are returned, or 404 if the playlist doesn't exist.
GET /videos/published
require_owned_video
Looks up only the video's ID and returns 404 unless it is one of this channel's videos.
404 check: GET /videos/{id}/analytics, /videos/{id}/traffic-sources, /analytics/videos/{id}/search-insights, /analytics/videos/{id}/related-videos/referrers, /comments/videos/{id}
reader.scalar(Video, "MIN", "published_at")
Returns the earliest publish date of this channel's videos; the route keeps its year, or nothing if there are no videos. It fills the year options in the period dropdowns.
GET /meta/date-range

Playlists

Handled in routes/playlists.py and routes/video_scope.py.

Read
Returns
Used by
queries.playlist_catalog
Returns one page of playlists for the Playlists table, plus the total count. Each playlist includes when its newest video was published, the total views of its videos and their total earnings in SGD. Given a playlist ID it returns just that playlist.
GET /playlists
GET /playlists/{id} (that one playlist)
require_playlist
Looks up only the playlist's ID and returns 404 if it doesn't exist, without adding up any totals.
404 check: /comments/playlists/{id}, and every endpoint that uses resolve_playlist_video_ids
queries.playlist_owned_video_ids
Returns the IDs of the channel's videos in a playlist, each listed once. resolve_playlist_video_ids runs it after require_playlist, and the playlist endpoints pass the list to the same reads the channel-wide endpoints use, which limits their results to the playlist.
GET /playlists/{id}/videos/stats
GET /playlists/{id}/videos
every GET /analytics/playlists/{id}… endpoint
GET /videos/published with a playlist ID

Daily analytics

Defined in database/analytics.py and database/queries.py.

Read
Returns
Used by
get_video_analytics
Returns one video's metrics for each day in the date range: views, watch time, revenue in USD and SGD, average view duration and percentage, likes, and subscribers gained and lost. Days with no data are filled with zeros so the chart has no gaps.
GET /videos/{id}/analytics
get_aggregated_analytics
Returns the same daily metrics added up across all matching videos, with one row per day for videos and one for Shorts. This feeds the main chart on the Analytics pages.
GET /analytics/videos
GET /analytics/playlists/{id}
queries.top_videos_by_views
Returns the top videos for the date range, ranked by views or by watch time, with each video's views, watch hours and earnings in SGD for that range.
GET /analytics/videos/top (top 10)
GET /analytics/playlists/{id}/top (top 10)

Traffic sources

Defined in database/traffic_sources.py.

Read
Returns
Used by
get_video_traffic_sources
Returns one video's views and watch time for each day and each traffic source, such as YouTube search, suggested videos or external sites. Missing days are filled with zeros.
GET /videos/{id}/traffic-sources
get_aggregated_traffic_sources
Returns daily views and watch time per traffic source, added up across all matching videos. This feeds the traffic source chart and table.
GET /analytics/traffic-sources
GET /analytics/playlists/{id}/traffic-sources
get_top_videos_by_traffic_source
Returns, for each traffic source, the videos that got the most views from it in the date range.
GET /analytics/traffic-sources/top (10 per source)
GET /analytics/playlists/{id}/traffic-sources/top (10 per source)

Search terms

Defined in database/queries.py. Search terms are stored by month, so the date range is widened to whole months.

Read
Returns
Used by
queries.search_term_totals
Returns the YouTube search terms that brought viewers to the matching videos, with the total views per term, most-viewed first. For one video, the route passes just that video's ID.
GET /analytics/search-insights
GET /analytics/search-insights/top (first 10)
GET /analytics/playlists/{id}/search-insights
GET /analytics/playlists/{id}/search-insights/top (first 10)
GET /analytics/videos/{id}/search-insights
queries.videos_by_search_term
Returns the videos viewers found through one search term, with the views each got, most-viewed first. This feeds the card that shows videos for the search term you pick.
GET /analytics/search-insights/videos
GET /analytics/playlists/{id}/search-insights/videos

Related videos

Defined in database/related_videos.py and database/queries.py. Related video data is stored by month, so the date range is widened to whole months.

Read
Returns
Used by
get_related_video_referrers
Returns the videos that sent viewers to this channel's videos through YouTube's Related Videos, with how many views each one sent, most first. The own setting chooses between referrers that are this channel's own videos and referrers from other channels, which includes any referrer whose details are unknown. It also returns total_named_views, the total across all referrers regardless of that setting, so the page can show each referrer's share.
GET /analytics/related-videos/referrers
GET /analytics/playlists/{id}/related-videos/referrers
GET /analytics/videos/{id}/related-videos/referrers
queries.related_video_destinations
Returns, for one referring video, which of this channel's videos it sent viewers to and how many views each got, most first. The video page calls it with its own video ID to show where that video sends viewers.
GET /analytics/related-videos/destinations
GET /analytics/playlists/{id}/related-videos/destinations

Comments

Defined in database/queries.py.

Read
Returns
Used by
queries.comment_feed
Returns one page of top-level comments plus the total count. Each comment includes its author's name and picture and the video it's on. Comments can be filtered by text, author, date, video title and type, and sorted newest, oldest or most liked. Given a video ID it covers that one video, with no video title or type filter. Given a playlist ID it covers that playlist's videos, and a video listed twice in the playlist doesn't show its comments twice.
GET /comments
GET /comments/videos/{id}
GET /comments/playlists/{id}

Sync

Defined in database/sync_runs.py and sync/status.py.

Read
Returns
Used by
get_sync_runs
Returns one page of past syncs for the History tab on the Sync page. Each sync lists its start time, its overall status (the worst status among its stages), how many stages ran, the rows fetched, written and deleted, and each stage's own record.
GET /sync/runs
sync.get_sync_status
Returns the live state of the current or most recent sync: whether one is running, whether a stop was requested, and each selected stage's state and progress message. It is read from memory, not the database.
GET /sync/status

Call chains

Each line shows the functions an endpoint calls, in order. queries.* definitions are run through reader.fetch or reader.fetch_joined. Other names without a prefix are database functions, except the require_* and resolve_* checks from routes/video_scope.py.

routes/videos.py

  • GET /videos → queries.video_catalog (count and page on one connection)
  • GET /videos/stats → get_video_stats
  • GET /videos/published → resolve_playlist_video_ids (only with a playlist ID): require_playlist (404 check) → queries.playlist_owned_video_ids → queries.videos_published
  • GET /videos/{id} → queries.video_catalog (that one video)
  • GET /videos/{id}/analytics → require_owned_video (404 check) → get_video_analytics
  • GET /videos/{id}/traffic-sources → require_owned_video (404 check) → get_video_traffic_sources

routes/playlists.py

  • GET /playlists → queries.playlist_catalog (count and page on one connection)
  • GET /playlists/{id} → queries.playlist_catalog (that one playlist)
  • GET /playlists/{id}/videos/stats → resolve_playlist_video_ids: require_playlist (404 check) → queries.playlist_owned_video_ids → get_video_stats
  • GET /playlists/{id}/videos → resolve_playlist_video_ids: require_playlist (404 check) → queries.playlist_owned_video_ids → queries.video_catalog (count and page on one connection)

routes/analytics.py — videos

  • GET /analytics/videos → get_aggregated_analytics
  • GET /analytics/videos/top → queries.top_videos_by_views
  • GET /analytics/traffic-sources → get_aggregated_traffic_sources
  • GET /analytics/traffic-sources/top → get_top_videos_by_traffic_source
  • GET /analytics/search-insights → queries.search_term_totals
  • GET /analytics/search-insights/top → queries.search_term_totals (top 10)
  • GET /analytics/search-insights/videos → queries.videos_by_search_term
  • GET /analytics/related-videos/referrers → get_related_video_referrers
  • GET /analytics/related-videos/destinations → queries.related_video_destinations
  • GET /analytics/videos/{id}/search-insights → require_owned_video (404 check) → queries.search_term_totals (that one video)
  • GET /analytics/videos/{id}/related-videos/referrers → require_owned_video (404 check) → get_related_video_referrers

routes/analytics.py — playlists

Every line starts with resolve_playlist_video_ids: require_playlist (404 check) → queries.playlist_owned_video_ids.

  • GET /analytics/playlists/{id} → get_aggregated_analytics
  • GET /analytics/playlists/{id}/top → queries.top_videos_by_views
  • GET /analytics/playlists/{id}/traffic-sources → get_aggregated_traffic_sources
  • GET /analytics/playlists/{id}/traffic-sources/top → get_top_videos_by_traffic_source
  • GET /analytics/playlists/{id}/search-insights → queries.search_term_totals
  • GET /analytics/playlists/{id}/search-insights/top → queries.search_term_totals (top 10)
  • GET /analytics/playlists/{id}/search-insights/videos → queries.videos_by_search_term
  • GET /analytics/playlists/{id}/related-videos/referrers → get_related_video_referrers
  • GET /analytics/playlists/{id}/related-videos/destinations → queries.related_video_destinations

routes/comments.py

  • GET /comments → queries.comment_feed
  • GET /comments/videos/{id} → require_owned_video (404 check) → queries.comment_feed (that video)
  • GET /comments/playlists/{id} → require_playlist (404 check) → queries.comment_feed (that playlist)

routes/metadata.py

  • GET /meta/date-range → reader.scalar(Video, "MIN", "published_at")

routes/synchronization.py

  • GET /sync/status → sync.get_sync_status (no database call)
  • POST /sync/stop → sync.request_stop
  • POST /sync/trigger → sync.validate_plan → sync.try_begin_sync → sync.execute_plan (in the background)
  • GET /sync/runs → get_sync_runs
