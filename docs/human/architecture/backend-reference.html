Backend reference

This page shows what each backend file does and which functions each API route calls.

Source revision ab9b0f4

Files

Top level

Starts the app and sets up logging.

server.py
Creates the app and prepares the database on startup.
logging_config.py
Sets up the application and sync log files.

routes/

The web API the frontend calls.

videos.py
Serves the Videos page and single-video data.
playlists.py
Serves the Playlists page and single-playlist data.
analytics.py
Serves the Analytics pages: charts, top videos, traffic sources, search terms, and related videos.
comments.py
Serves the comment feeds for the channel, a video, or a playlist.
synchronization.py
Starts and stops syncs, reports progress, and returns sync history.
metadata.py
Returns the earliest publish year for the year dropdowns.
video_scope.py
Returns 404 for a missing video or playlist, and loads a playlist's video IDs. Defines no endpoints.
daily_series.py
Holds the settings for filling missing days in chart data. Defines no endpoints.

database/

Everything that touches SQLite.

dataclasses/
One data class per table, such as Video or Comment. They only hold values.
tables.py
Maps each class to its table and key columns.
filters.py
Turns a list of conditions into a SQL WHERE.
reader.py
Runs every read and returns data classes.
writer.py
Runs every insert, update and delete.
queries.py
Holds the SQL for joined, grouped and ranked reads.
video_statistics.py
Calculates the Legacy/New statistics shown in the stats bar.
connection.py
Opens database connections and creates the tables.

sync/

Downloads data from YouTube and stores it.

orchestration.py
Runs a sync plan stage by stage and records each stage's result.
stages.py
Contains the code for each of the nine stages.
plans.py
Checks that a requested plan is valid and sets the order stages run in.
status.py
Tracks live progress and handles stop requests.
coverage.py
Works out which months still need downloading.
write_preparation.py
Turns a month of search terms or referrers into data classes.
monthly_insights.py
Splits date ranges into calendar months.
scheduler.py
Is an unused daily-sync helper; nothing calls it.

youtube/

Talks to Google. Only sync/ uses it.

data_api.py
Fetches channel info, videos, playlists, and comments from the YouTube Data API.
analytics_api.py
Fetches daily metrics, traffic sources, search terms, and related videos from the YouTube Analytics API.
auth.py
Handles the Google sign-in and keeps the token fresh.

Schema and scripts

schema.sql
Defines the database tables.
scripts/issue-48-migration.py
Adds the videos.own column to an older database.
scripts/issue-62-migration.py
Fills in sync coverage for an older database.

Route functions

What each read returns and which endpoints use it. queries. names are SQL in database/queries.py, run through the reader.

Videos

Handled in routes/videos.py and routes/metadata.py.

Read
Returns
Used by
queries.video_catalog
One page of videos with their lifetime earnings and watch hours.
GET /videos
GET /videos/{id} (that one video)

The stats bar numbers: legacy and new video counts, views and earnings, plus comment and privacy totals.

Videos published in the date range, used to mark upload days on the charts.

reader.scalar(Video, "MIN", "published_at")
The earliest publish year, for the year dropdowns.
GET /meta/date-range

Call chains

The functions each endpoint calls, in order. "Filled" means missing days are added.

routes/videos.py

  • GET /videos → queries.video_catalog (count and page on one connection)
  • GET /videos/stats → get_video_stats
  • GET /videos/published → resolve_playlist_video_ids (only with a playlist ID): require_playlist (404 check) → queries.playlist_owned_video_ids → queries.videos_published
  • GET /videos/{id} → queries.video_catalog (that one video)
  • GET /videos/{id}/analytics → require_owned_video (404 check) → queries.video_daily_analytics (filled)
  • GET /videos/{id}/traffic-sources → require_owned_video (404 check) → queries.video_daily_traffic_sources (filled)

routes/playlists.py

  • GET /playlists → queries.playlist_catalog (count and page on one connection)
  • GET /playlists/{id} → queries.playlist_catalog (that one playlist)
  • GET /playlists/{id}/videos/stats → resolve_playlist_video_ids: require_playlist (404 check) → queries.playlist_owned_video_ids → get_video_stats
  • GET /playlists/{id}/videos → resolve_playlist_video_ids: require_playlist (404 check) → queries.playlist_owned_video_ids → queries.video_catalog (count and page on one connection)

routes/analytics.py — videos

  • GET /analytics/videos → queries.daily_analytics_totals (filled)
  • GET /analytics/videos/top → queries.top_videos_by_views
  • GET /analytics/traffic-sources → queries.daily_traffic_source_totals (filled)
  • GET /analytics/traffic-sources/top → queries.traffic_source_video_totals → reader.group_by (10 per source)
  • GET /analytics/search-insights → queries.search_term_totals
  • GET /analytics/search-insights/top → queries.search_term_totals (top 10)
  • GET /analytics/search-insights/videos → queries.videos_by_search_term
  • GET /analytics/related-videos/referrers → queries.related_video_referrers
  • GET /analytics/related-videos/destinations → queries.related_video_destinations
  • GET /analytics/videos/{id}/search-insights → require_owned_video (404 check) → queries.search_term_totals (that one video)
  • GET /analytics/videos/{id}/related-videos/referrers → require_owned_video (404 check) → queries.related_video_referrers (that one video)

routes/analytics.py — playlists

Every line starts with resolve_playlist_video_ids: require_playlist (404 check) → queries.playlist_owned_video_ids.

  • GET /analytics/playlists/{id} → queries.daily_analytics_totals (filled)
  • GET /analytics/playlists/{id}/top → queries.top_videos_by_views
  • GET /analytics/playlists/{id}/traffic-sources → queries.daily_traffic_source_totals (filled)
  • GET /analytics/playlists/{id}/traffic-sources/top → queries.traffic_source_video_totals → reader.group_by (10 per source)
  • GET /analytics/playlists/{id}/search-insights → queries.search_term_totals
  • GET /analytics/playlists/{id}/search-insights/top → queries.search_term_totals (top 10)
  • GET /analytics/playlists/{id}/search-insights/videos → queries.videos_by_search_term
  • GET /analytics/playlists/{id}/related-videos/referrers → queries.related_video_referrers
  • GET /analytics/playlists/{id}/related-videos/destinations → queries.related_video_destinations

routes/comments.py

  • GET /comments → queries.comment_feed
  • GET /comments/videos/{id} → require_owned_video (404 check) → queries.comment_feed (that video)
  • GET /comments/playlists/{id} → require_playlist (404 check) → queries.comment_feed (that playlist)

routes/metadata.py

  • GET /meta/date-range → reader.scalar(Video, "MIN", "published_at")

routes/synchronization.py

  • GET /sync/status → sync.get_sync_status (no database call)
  • POST /sync/stop → sync.request_stop
  • POST /sync/trigger → sync.validate_plan → sync.try_begin_sync → sync.execute_plan (in the background)
  • GET /sync/runs → queries.sync_batches → reader.select(SyncRun) for the page's stages → reader.group_by
