Backend reference

This page shows what each backend file does and which functions each API route calls.

Source revision 7c617f2

Files

Top level

Starts the app and sets up logging.

server.py
Creates the FastAPI app and prepares the database on startup.
logging_config.py
Sets up the application and sync log files.

routes/

The web API the frontend calls. Each handler checks its input and passes the work to database/, or to sync/ for the sync endpoints. Details: docs/references/api.md.

videos.py
Serves the Videos page and single-video data.
playlists.py
Serves the Playlists page and single-playlist data.
analytics.py
Serves the Analytics pages: charts, top videos, traffic sources, search terms, and related videos.
comments.py
Serves the comment feeds for the channel, a video, or a playlist.
synchronization.py
Starts and stops syncs, reports progress, and returns sync history.
metadata.py
Returns the earliest publish year for the year dropdowns.
video_scope.py
Looks up the videos in a playlist for the playlist statistics and playlist analytics endpoints, returning 404 if the playlist doesn't exist. Defines no endpoints.

database/

Reads and writes SQLite, one file per kind of data. Details: docs/references/database.md.

videos.py
Stores videos and answers the video list, detail, and stats queries.
playlists.py
Stores playlists and the videos in them.
analytics.py
Stores daily video metrics and answers the chart and top-video queries.
traffic_sources.py
Stores daily views per traffic source.
search_terms.py
Stores the monthly search terms that led viewers to each video.
related_videos.py
Stores which videos sent viewers to each video through Related Videos.
comments.py
Stores comments and their authors, and answers the comment feeds.
sync_runs.py
Stores the history of sync runs.
sync_coverage.py
Records which months have already been synced for each video.
fx_rates.py
Stores daily USD to SGD exchange rates.
connection.py
Opens database connections and creates the tables.

sync/

Downloads data from YouTube and stores it. Details: docs/references/sync.md.

orchestration.py
Runs a sync plan stage by stage and records each stage's result.
stages.py
Contains the code for each of the nine stages.
plans.py
Checks that a requested plan is valid and sets the order stages run in.
status.py
Tracks live progress and handles stop requests.
coverage.py
Works out which months still need downloading.
monthly_insights.py
Splits date ranges into calendar months.
scheduler.py
Is an unused daily-sync helper; nothing calls it.

youtube/

Talks to Google. Only sync/ uses it. Details: docs/references/sync.md.

data_api.py
Fetches channel info, videos, playlists, and comments from the YouTube Data API.
analytics_api.py
Fetches daily metrics, traffic sources, search terms, and related videos from the YouTube Analytics API.
auth.py
Handles the Google sign-in and keeps the token fresh.

Schema and scripts

schema.sql
Defines the database tables.
scripts/issue-48-migration.py
Adds the videos.own column to an older database.
scripts/issue-62-migration.py
Fills in sync coverage for an older database.

Route functions

What each function the routes call gives back, and which endpoints use it. These only count this channel's own videos. Videos from other channels that are stored only because they sent viewers here through Related Videos never appear.

Videos

Defined in database/videos.py.

Function
Returns
Used by
get_all_videos
Returns one page of videos for the Videos table, plus the total count for paging. Each video includes its lifetime earnings in SGD and lifetime watch hours. The list can be sorted and filtered by title, publish date, type and privacy.
GET /videos
get_video_stats
Returns the numbers in the stats bar on the Videos and Analytics pages. Videos and Shorts are each split into legacy (published before the start date) and new (published within the date range), and each group gets a count plus its views and earnings within the date range. It also returns lifetime comment totals and how many videos are public, private and unlisted. With no date range it uses the full span of stored analytics. Given a list of video IDs, it returns the same numbers for just those videos (each counted once), and its default date range comes from their analytics only.
GET /videos/stats
GET /playlists/{id}/videos/stats (the playlist's video IDs)
get_videos_published
Returns the videos published within the date range (ID, title, date, thumbnail and type), oldest first. The charts use it to mark the days videos were uploaded. Given a playlist ID, it only returns that playlist's videos.
GET /videos/published
get_owned_video
Returns one video with its lifetime earnings and watch hours, or nothing if the ID isn't one of this channel's videos.
GET /videos/{id}
404 check: GET /videos/{id}/analytics, /videos/{id}/traffic-sources, /analytics/videos/{id}/search-insights, /analytics/videos/{id}/related-videos/referrers, /comments/videos/{id}
get_earliest_published_year
Returns the year the oldest video was published, or nothing if there are no videos. It fills the year options in the period dropdowns.
GET /meta/date-range

Playlists

Defined in database/playlists.py.

Function
Returns
Used by
get_all_playlists
Returns one page of playlists for the Playlists table, plus the total count. Each playlist includes when its newest video was published, the total views of its videos and their total earnings in SGD.
GET /playlists
get_playlist
Returns one playlist with the same totals, or nothing if it doesn't exist.
GET /playlists/{id}
404 check: GET /playlists/{id}/videos and /comments/playlists/{id}
playlist_exists
Says whether a playlist exists, without adding up any totals.
404 check: GET /playlists/{id}/videos/stats and every /analytics/playlists/{id}… endpoint
get_playlist_video_ids
Returns the IDs of the channel's videos in a playlist, each listed once. The playlist statistics and analytics endpoints pass this list to the same functions the channel-wide endpoints use, which limits their results to the playlist.
GET /playlists/{id}/videos/stats
every GET /analytics/playlists/{id}… endpoint
get_playlist_videos
Returns one page of a playlist's videos for its Videos tab, plus the total count, with the same sorting, filters and lifetime totals as get_all_videos.
GET /playlists/{id}/videos

Daily analytics

Defined in database/analytics.py.

Function
Returns
Used by
get_video_analytics
Returns one video's metrics for each day in the date range: views, watch time, revenue in USD and SGD, average view duration and percentage, likes, and subscribers gained and lost. Days with no data are filled with zeros so the chart has no gaps.
GET /videos/{id}/analytics
get_aggregated_analytics
Returns the same daily metrics added up across all matching videos, with one row per day for videos and one for Shorts. This feeds the main chart on the Analytics pages.
GET /analytics/videos
GET /analytics/playlists/{id}
get_top_videos_by_views
Returns the top videos for the date range, ranked by views or by watch time, with each video's views, watch hours and earnings in SGD for that range.
GET /analytics/videos/top (top 10)
GET /analytics/playlists/{id}/top (top 10)

Traffic sources

Defined in database/traffic_sources.py.

Function
Returns
Used by
get_video_traffic_sources
Returns one video's views and watch time for each day and each traffic source, such as YouTube search, suggested videos or external sites. Missing days are filled with zeros.
GET /videos/{id}/traffic-sources
get_aggregated_traffic_sources
Returns daily views and watch time per traffic source, added up across all matching videos. This feeds the traffic source chart and table.
GET /analytics/traffic-sources
GET /analytics/playlists/{id}/traffic-sources
get_top_videos_by_traffic_source
Returns, for each traffic source, the videos that got the most views from it in the date range.
GET /analytics/traffic-sources/top (10 per source)
GET /analytics/playlists/{id}/traffic-sources/top (10 per source)

Search terms

Defined in database/search_terms.py. Search terms are stored by month, so the date range is widened to whole months.

Function
Returns
Used by
get_search_terms
Returns the YouTube search terms that brought viewers to the matching videos, with the total views per term, most-viewed first.
GET /analytics/search-insights
GET /analytics/search-insights/top (first 10)
GET /analytics/playlists/{id}/search-insights
GET /analytics/playlists/{id}/search-insights/top (first 10)
get_video_search_terms
Returns the same list for a single video.
GET /analytics/videos/{id}/search-insights
get_videos_by_search_term
Returns the videos viewers found through one search term, with the views each got, most-viewed first. This feeds the card that shows videos for the search term you pick.
GET /analytics/search-insights/videos
GET /analytics/playlists/{id}/search-insights/videos

Related videos

Defined in database/related_videos.py. Related video data is stored by month, so the date range is widened to whole months.

Function
Returns
Used by
get_related_video_referrers
Returns the videos that sent viewers to this channel's videos through YouTube's Related Videos, with how many views each one sent, most first. The own setting chooses between referrers that are this channel's own videos and referrers from other channels, which includes any referrer whose details are unknown. It also returns total_named_views, the total across all referrers regardless of that setting, so the page can show each referrer's share.
GET /analytics/related-videos/referrers
GET /analytics/playlists/{id}/related-videos/referrers
GET /analytics/videos/{id}/related-videos/referrers
get_related_video_destinations
Returns, for one referring video, which of this channel's videos it sent viewers to and how many views each got, most first. The video page calls it with its own video ID to show where that video sends viewers.
GET /analytics/related-videos/destinations
GET /analytics/playlists/{id}/related-videos/destinations

Comments

Defined in database/comments.py.

Function
Returns
Used by
get_comments
Returns one page of top-level comments across the channel, plus the total count. Each comment includes its author's name and picture and the video it's on. Comments can be filtered by text, author, date, video title and type, and sorted newest, oldest or most liked.
GET /comments
get_video_comments
Returns the same for one video. Video title and type aren't filters here, since the video is already fixed.
GET /comments/videos/{id}
get_playlist_comments
Returns the same for the videos in one playlist. A video listed twice in the playlist doesn't show its comments twice.
GET /comments/playlists/{id}

Sync

Defined in database/sync_runs.py and sync/status.py.

Function
Returns
Used by
get_sync_runs
Returns one page of past syncs for the History tab on the Sync page. Each sync lists its start time, its overall status (the worst status among its stages), how many stages ran, the rows fetched, written and deleted, and each stage's own record.
GET /sync/runs
sync.get_sync_status
Returns the live state of the current or most recent sync: whether one is running, whether a stop was requested, and each selected stage's state and progress message. It is read from memory, not the database.
GET /sync/status

Call chains

Each line shows the functions an endpoint calls, in order. Names without a prefix are database functions.

routes/videos.py

  • GET /videos → get_all_videos
  • GET /videos/stats → get_video_stats
  • GET /videos/published → get_videos_published
  • GET /videos/{id} → get_owned_video
  • GET /videos/{id}/analytics → get_owned_video (404 check) → get_video_analytics
  • GET /videos/{id}/traffic-sources → get_owned_video (404 check) → get_video_traffic_sources

routes/playlists.py

  • GET /playlists → get_all_playlists
  • GET /playlists/{id} → get_playlist
  • GET /playlists/{id}/videos/stats → resolve_playlist_video_ids: playlist_exists (404 check) → get_playlist_video_ids → get_video_stats
  • GET /playlists/{id}/videos → get_playlist (404 check) → get_playlist_videos

routes/analytics.py — videos

  • GET /analytics/videos → get_aggregated_analytics
  • GET /analytics/videos/top → get_top_videos_by_views
  • GET /analytics/traffic-sources → get_aggregated_traffic_sources
  • GET /analytics/traffic-sources/top → get_top_videos_by_traffic_source
  • GET /analytics/search-insights → get_search_terms
  • GET /analytics/search-insights/top → get_search_terms (top 10)
  • GET /analytics/search-insights/videos → get_videos_by_search_term
  • GET /analytics/related-videos/referrers → get_related_video_referrers
  • GET /analytics/related-videos/destinations → get_related_video_destinations
  • GET /analytics/videos/{id}/search-insights → get_owned_video (404 check) → get_video_search_terms
  • GET /analytics/videos/{id}/related-videos/referrers → get_owned_video (404 check) → get_related_video_referrers

routes/analytics.py — playlists

  • GET /analytics/playlists/{id} → resolve_playlist_video_ids: playlist_exists (404 check) → get_playlist_video_ids → get_aggregated_analytics
  • GET /analytics/playlists/{id}/top → resolve_playlist_video_ids: playlist_exists (404 check) → get_playlist_video_ids → get_top_videos_by_views
  • GET /analytics/playlists/{id}/traffic-sources → resolve_playlist_video_ids: playlist_exists (404 check) → get_playlist_video_ids → get_aggregated_traffic_sources
  • GET /analytics/playlists/{id}/traffic-sources/top → resolve_playlist_video_ids: playlist_exists (404 check) → get_playlist_video_ids → get_top_videos_by_traffic_source

  • GET /analytics/playlists/{id}/search-insights/videos → resolve_playlist_video_ids: playlist_exists (404 check) → get_playlist_video_ids → get_videos_by_search_term
  • GET /analytics/playlists/{id}/related-videos/referrers → resolve_playlist_video_ids: playlist_exists (404 check) → get_playlist_video_ids → get_related_video_referrers
  • GET /analytics/playlists/{id}/related-videos/destinations → resolve_playlist_video_ids: playlist_exists (404 check) → get_playlist_video_ids → get_related_video_destinations

routes/comments.py

  • GET /comments → get_comments
  • GET /comments/videos/{id} → get_owned_video (404 check) → get_video_comments
  • GET /comments/playlists/{id} → get_playlist (404 check) → get_playlist_comments

routes/metadata.py

  • GET /meta/date-range → get_earliest_published_year

routes/synchronization.py
