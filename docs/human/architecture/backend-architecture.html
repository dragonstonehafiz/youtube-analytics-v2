Backend architecture

This page shows what each part of the backend does and how the parts connect.

Source revision 53b29e4

What each part does

server.py

Starts the web server, adds the routes, and prepares the database.

routes/

The web API: one file per area, each answering frontend requests with data from the database.

database/

The only code that touches SQLite: data classes, the reader, the writer, and the reports that run joined and grouped reads.

sync/

Downloads data from YouTube into the database when you run a sync.

youtube/

Signs in to Google and calls the YouTube APIs.

logging_config.py

Writes the application and sync log files.

schema.sql

Defines the database tables.

scripts/

One-off migrations for older databases, run by hand.

How they fit: the frontend calls routes/, which reads from database/. Separately, sync/ pulls data through youtube/ and writes it into database/.

Package dependencies

database/

Imports no other application package.

youtube/

Never touches the database.

routes/

Reads the database and never calls youtube/.

sync/

The only package that calls youtube/ and writes to the database.

Main call paths

Read request

server.appincludes routes.router
Route handlerChecks the video or playlist exists
ReportHolds the SQL, fills missing days, and shapes the result
ReaderRuns the SQL and returns data classes
Connectionconnection.get_connection() → SQLite
ResponseThe report's result becomes JSON

A channel URL and its playlist URL share one handler. On the playlist URL, the handler first loads the playlist's video IDs and passes them to the report. Single-video handlers call the report with that one video's ID.

Sync

trigger_syncValidates the plan and starts it in the background
execute_planRuns the serial stages, then the analytics stages on 2 threads
_run_tracked_stage → _run_stageRecords each stage as a sync_runs row
stages.sync_*Does the stage's work, checking for a stop
youtube.fetch_* / iter_*Fetches data, then saves it through the writer

sync.run_plan() and sync/scheduler.py sit outside this path: nothing calls start_background_scheduler(), so neither runs.

Observations

Broad modules

sync/stages.py holds all nine stages.

Unused at runtime

start_background_scheduler(), synced_today(), and run_plan().

Re-export files

The database, sync and youtube packages re-export their public names (20, 31 and 15). Report modules in database/reports/ are imported directly instead.
