Backend architecture

This page shows what each part of the backend does and how the parts connect.

Source revision 8f69e1f

What each part does

server.py

Starts the backend: creates the web server, plugs in the API routes, and prepares the database when the app launches.

routes/

The web API. Receives each request from the frontend, checks it, and answers with data from the database. One file per area: videos, playlists, analytics, comments, sync, metadata.

database/

The only code that reads or writes SQLite. Stores what sync downloads and answers the questions the routes ask. One file per kind of data.

sync/

The data importer. When you press Sync selected, it decides what to download, runs the steps in order, tracks progress, and lets you stop it.

youtube/

Talks to Google: signs in with OAuth and calls the YouTube Data and Analytics APIs. Only sync uses it.

logging_config.py

Writes the application and sync log files.

schema.sql

Defines the database tables. Run on every startup, creating only the tables that are missing.

scripts/

One-off migrations that bring an older database up to date. Run by hand, never by the app.

How they fit: the frontend calls routes/, which reads from database/. Separately, sync/ pulls data through youtube/ and writes it into database/. Backend reference describes every file individually.

Package dependencies

database/

Imports no other application package — the shared bottom layer.

youtube/

Never touches the database. Only sync/stages.py moves API results into database/.

routes/

Never calls youtube/.

sync/

The only package that calls youtube/, and the only caller of database/'s write helpers (every upsert_* and delete_*). Only routes/ imports it.

Observations

Broad modules

sync/stages.py holds all nine stage implementations plus their shared helpers. database/videos.py mixes catalog writes, listing, ID lists, both stats helpers, and the pruning delete.

Unused at runtime

Database functions get_last_analytics_date(), get_last_traffic_source_date(), get_last_search_terms_month(), get_last_related_videos_month(), get_fx_rates() (the last two used only by tests); and start_background_scheduler(), synced_today(), run_plan(), get_last_successful_run_completed_at().

Re-export files

Three package __init__.py files re-export every public name (database 59, sync 31, youtube 15); routes/__init__.py combines the six routers.
