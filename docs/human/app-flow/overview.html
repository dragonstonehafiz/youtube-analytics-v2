Overview

This page shows how data moves from the browser to the database, and from YouTube into the database.

The browser never talks to YouTube. Only the backend's sync engine does, and only when a sync is triggered.

Two independent paths

Path 1: user action → response

1 · User actionA filter, tab, sort or page change updates the URL.
2 · Effect runsThe card's useEffect re-runs and calls api.ts.
3 · api.tsSends the request to the backend.
4 · RouteChecks the video or playlist exists, then calls a report for data.
5 · ReportThe report runs its SQL through the reader and returns a finished result.
6 · RenderThe card re-renders with the JSON.

Playlist-scoped analytics routes first resolve the playlist's member video IDs, then pass them to the same report the channel-wide route uses. Every trigger per page is in Requests.

Path 2: YouTube → database

1 · PlanThe Sync page builds a plan from the checked stages.
2 · AcceptPOST /sync/trigger validates the plan and starts it in the background.
3 · Serial stagesplaylists → videos → pruning → comments → fx_rates, stopping at the first failure.
4 · Analytics workersThe four Analytics API stages run on up to 2 threads.
5 · FetchEach stage calls YouTube or Yahoo Finance.
6 · WriteEach fetched record becomes a data class and is saved through the writer.

Live status

Kept in memory and polled through GET /sync/status.

Stop

POST /sync/stop stops the sync at the next safe point.

History

Past syncs are listed through GET /sync/runs.

Stage semantics, scopes, coverage, and failure handling: docs/references/sync.md.

Sync triggers actually wired

TriggerWired?Path
Sync selected on /syncYes — the only triggerSync.tsx → POST /sync/trigger → execute_plan()
Automatic sync on backend startupNostart_background_scheduler() and synced_today() exist in sync/scheduler.py and are exported from sync, but server.py's lifespan does not call them
StopCancels onlySync.tsx → POST /sync/stop → sync.request_stop()

sync.run_plan() (reserve-then-execute) has no caller outside start_background_scheduler(), so it is also unused at runtime.

Backend startup and shutdown

  1. Log "Application startup"
  2. database.init_db() — creates any missing tables from schema.sql.
  3. database.writer.update(SyncRun(status="incomplete"), where=…running…) — marks rows left running by a killed process as incomplete.
  4. Serve requests
  5. Log "Application shutdown" — in a finally block.

No YouTube call and no sync happens at startup. OAuth runs the first time a sync stage builds a YouTube client (youtube/auth.py).
