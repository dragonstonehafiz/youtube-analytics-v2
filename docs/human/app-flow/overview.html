Overview

The browser never talks to YouTube. Only the backend's sync engine does, and only when a sync is triggered.

Two independent paths

Path 1: user action → response

1 · User actionFilter, tab, sort and page values are URL query params, written with useReplaceSearchParams(). Typed search commits after 300 ms idle.
2 · Effect runsA useEffect whose dependencies changed calls api.ts. track() marks the card loading and drops superseded responses.
3 · api.tsBuilds http://localhost:8000<path>?<params>, omitting empty params.
4 · RouteChecks a parent video/playlist exists (404), then reads through database.reader or calls a report function.
5 · QueryThe reader runs parameterized SQL that selects only the needed columns and returns data classes; the route turns them into JSON with to_dict(). Reports return finished dicts.
6 · RenderJSON lands in the card's RequestState; the card re-renders.

Playlist-scoped analytics routes first resolve the playlist's member video IDs, then pass them to the same read the channel-wide route uses. Every trigger per page is in Requests.

Path 2: YouTube → database

1 · PlanSync page builds a plan from checked stages and their period/scope selectors.
2 · AcceptPOST /sync/trigger: validate_plan (400), try_begin_sync (409), schedule execute_plan, reply {queued: true}.
3 · Serial stagesplaylists → videos → pruning → comments → fx_rates, fail-fast.
4 · Analytics workersvideo_analytics, video_traffic_sources, search_insights, related_video_insights on ≤ 2 threads.
5 · FetchData API v3, Analytics API v2, or yfinance for FX.
6 · WriteUpserts, one sync_runs row per started stage, sync_coverage months.

Live status

Held in memory in sync/status.py, served by GET /sync/status, polled every 5 s by the top navigation and the Sync page.

Stop

POST /sync/stop sets a flag checked at safe checkpoints; in-flight requests and writes finish first.

History

Finished stages are read back with GET /sync/runs on the Sync page's History tab.

Stage semantics, scopes, coverage, and failure handling: docs/references/sync.md.

Automatic sync on backend startupNostart_background_scheduler() and synced_today() exist in sync/scheduler.py and are exported from sync, but server.py's lifespan does not call them
StopCancels onlySync.tsx → POST /sync/stop → sync.request_stop()

sync.run_plan() (reserve-then-execute) has no caller outside start_background_scheduler(), so it is also unused at runtime.

Backend startup and shutdown

  1. Log "Application startup"
  2. database.init_db() — creates any missing tables from schema.sql.
  3. database.mark_incomplete_sync_runs() — marks rows left running by a killed process as incomplete.
  4. Serve requests
  5. Log "Application shutdown" — in a finally block.

No YouTube call and no sync happens at startup. OAuth runs the first time a sync stage builds a YouTube client (youtube/auth.py).
