Backend

“Top 10 search terms” routes

2 routes

Serve only the ten biggest search terms instead of the whole list.

Where
GET /analytics/search-insights/top (get_top_search_terms) and GET /analytics/playlists/{playlist_id}/search-insights/top (get_playlist_top_search_terms) in routes/analytics.py
Does
Runs queries.search_term_totals(…, limit=10) through the reader with the usual date, type, privacy and title filters, channel-wide or for one playlist, and returns {"items": [{search_term, views}, …]}.
Meant for
A “top search terms” view that needs only the leaders, without downloading every term.
Why dead
The pages call …/search-insights for the full list, because the donut's “Other” total and the term dropdown need every term. The frontend wrappers for these routes exist but are never called. The /top routes are the main routes with limit=10 hard-coded; the main routes take no limit parameter, unlike …/search-insights/videos.

Uncalled API wrappers

3 functions

Fetch helpers in api.ts for data the pages load another way.

Where
getTopSearchTerms, getPlaylistTopSearchTerms, getPlaylistAggregatedAnalytics in api.ts
Does
The first two call the two “top 10 search terms” routes and return {items: SearchTermRow[]}. The third calls /analytics/playlists/{id} and returns the playlist's daily analytics.
Meant for
Loading only the top search terms for the channel or a playlist; loading a playlist's chart data.
Why dead
Pages use getSearchTerms / getPlaylistSearchTerms for the full term list. getPlaylistAggregatedAnalytics calls the same URL as getPlaylistAnalytics, which PlaylistAnalytics uses.
