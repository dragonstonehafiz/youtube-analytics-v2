Repeated code

Code written more than once in the backend and frontend, ordered by number of copies. Each card says what is repeated, where, and what differs between copies. Tests are not counted. Observations only; none prescribes a refactor.

Source revision 8c18975

Backend

Video filter conditions

×12

Each query function builds its own WHERE list for the same video filters, one if per filter.

Where
database/: analytics.py (2), traffic_sources.py (2), videos.py (4), playlists.py, search_terms.py, related_videos.py, comments.py
Differs
Only the date column (va.date, c.published_at, month bounds). comments.py has no privacy filter.
if content_type:
    conditions.append("v.content_type = ?")
    params.append(content_type)
if privacy_status:
    conditions.append("v.privacy_status = ?")
    params.append(privacy_status)
if title:
    conditions.append("(v.title LIKE ? OR v.id LIKE ?)")
    params.append(f"%{title}%")
    params.append(f"%{title}%")

Video or playlist lookup, and the message text.

Channel / playlist route twins

×9 pairs

Every playlist analytics endpoint copies its channel-wide endpoint: same five Query parameters, same database call, plus video_ids=_resolve_playlist_video_ids(playlist_id).

Where

The playlist_id path parameter and the video_ids argument.

Differs
Nothing.

Sync-run status updates

×3

Three functions run the same UPDATE sync_runs SET status, completed_at, rows_* statement.

Where

The status value; fail_sync_run also sets error_message.

Daily per-video sync stages

×2

Two stages are almost line for line the same: loop over owned videos, skip ones without a publish date, work out the missing date ranges, stream rows, upsert, record coverage, log.

Where
sync/stages.py: sync_video_analytics, sync_video_traffic_sources
Differs
The stage key, the youtube.iter_* fetcher and the database.upsert_* writer.

Monthly per-video sync stages

×2

Same shape as above for monthly data, including the identical scope year/all/incremental window logic.

Where
sync/stages.py: sync_search_insights, sync_related_video_insights
Differs
Fetcher, writer, and the related stage collects referrer IDs to resolve afterwards.

Monthly insight storage

×2

Both modules define the same _MONTH_RE, validate rows, sum views per key, drop zero-view rows, upsert, and have a get_last_*_month.

Where
database/search_terms.py, database/related_videos.py (connection.py has a related _MONTH_PREFIX_RE)
Differs
Key column (search_term vs referrer_video_id); related videos also checks the target is owned.

Zero-fill helpers

×2

Walk every date in the range, add a zero row for each missing key, then trim trailing dates that had no real data.

Where
_zero_fill_analytics in database/analytics.py, _zero_fill_traffic_sources in database/traffic_sources.py
Differs
The second key (content_type vs traffic_source_type) and how the zero row is built.

YouTube client helpers

×2

Both API clients define their own _noop_checkpoint() (identical) and _log_page() (same owner/name log fields).

Where
youtube/data_api.py, youtube/analytics_api.py
Differs
_log_page logs a page token and anomalies in one, a start_index in the other.

Ownership bool coercion

×2

Convert SQLite's 0/1 ownership column to a Python bool on each returned row.

Where
_coerce_own in database/videos.py, _coerce_referrer_own in database/related_videos.py
Differs
Column name; the referrer version keeps NULL as None.

Frontend code

Optional query parameters in api.ts

×14

Wrappers spell out each optional filter as a spread so empty values are left out, even though buildUrl already skips empty values.

Where
api.ts: start_date/end_date spread in 14 wrappers, title in 8, content_type and privacy_status in 7. Most playlist wrappers also mirror a channel wrapper.
Differs
Which filters a wrapper accepts. Newer wrappers take a query object instead.
...(startDate && { start_date: startDate }), ...(endDate && { end_date: endDate }),
...(contentType && { content_type: contentType }), ...(privacyStatus && { privacy_status: privacyStatus })
